## การเข้าสู่ระบบ

หน้าแรกของระบบมีปุ่มให้เลือก 2 แบบ: **«คลัง VDA»** (ร้านค้า) และ **«เซลล์ / Admin»**

### ร้านค้าและคลัง VDA — ใช้อีเมลและรหัสผ่าน

กรอกอีเมลของร้านแล้วกด **«ถัดไป»** ระบบจะพาไปตามขั้นตอนที่ตรงกับสถานะบัญชีเอง

```
กรอกอีเมล → «ถัดไป»
   │
   ├─ ยังไม่มีบัญชี          → เลือก VDA ของร้าน → «ส่งคำขอใช้งาน» → รอแอดมินอนุมัติ
   ├─ ส่งคำขอแล้ว            → ขึ้นกล่อง "บัญชีของคุณรอการอนุมัติจากแอดมิน"
   ├─ ถูกปฏิเสธ              → ขึ้นกล่อง "บัญชีนี้ไม่ได้รับสิทธิ์เข้าใช้งาน" โปรดติดต่อแอดมิน
   ├─ อนุมัติแล้วแต่ยังไม่ตั้งรหัส → กรอก **รหัสตั้งค่าจากแอดมิน** + ตั้งรหัสผ่านใหม่ → «ตั้งรหัสและเข้าสู่ระบบ»
   └─ มีบัญชีครบถ้วนแล้ว      → กรอกรหัสผ่าน → «เข้าสู่ระบบ»
```

**รหัสตั้งค่าครั้งแรก** เป็นรหัส 8 ตัว รูปแบบ `XXXX-XXXX` (เช่น `ABCD-2345`) ที่แอดมินส่งให้ร้าน
เมื่อ **อนุมัติคำขอ · เพิ่มบัญชีให้ · หรือรีเซ็ตรหัส**
- ใช้ได้ **ครั้งเดียว** และ **ภายใน 72 ชั่วโมง**
- ยังไม่ได้รหัส หรือรหัสหมดอายุ → ติดต่อแอดมินให้ออกรหัสใหม่
- รหัสผ่านที่ตั้งต้องมี **อย่างน้อย 8 ตัวอักษร** และพิมพ์ยืนยันให้ตรงกัน

**กรณีลืมรหัสผ่าน** กรอกอีเมลจนถึงช่องรหัสผ่าน แล้วกด **«ลืมรหัสผ่าน?»** ระบบจะแจ้ง
"ส่งคำขอรีเซ็ตรหัสแล้ว — โปรดติดต่อแอดมินเพื่อยืนยัน" (**ไม่มีอีเมลส่งออกไป**) แอดมินจะรีเซ็ตแล้ว
ส่งรหัสตั้งค่าใหม่ให้ ร้านกรอกอีเมลอีกครั้งแล้วตั้งรหัสผ่านใหม่ด้วยรหัสนั้น

> **เดิมสามารถเข้าใช้งานโดยเลือกรหัส VDA เท่านั้น ไม่ต้องใช้รหัสผ่าน ปัจจุบันยกเลิกวิธีดังกล่าวแล้ว**
> เนื่องจากระบบเปิดให้เข้าถึงผ่านอินเทอร์เน็ต ผู้ที่ทราบรหัส VDA จะสามารถสั่งสินค้าแทนร้านค้าได้
> หากร้านค้ายังไม่มีบัญชี โปรดแจ้งแอดมินเพื่อดำเนินการเปิดให้

### เซลล์ Admin และ Creator — ใช้บัญชี Microsoft ขององค์กร

เลือก **«เซลล์ / Admin»** แล้วเข้าสู่ระบบด้วยอีเมลของบริษัท ไม่ต้องกำหนดรหัสผ่านแยกต่างหาก

- **เซลล์เข้าได้เมื่ออีเมลถูกผูกกับรหัสเซลล์แล้วเท่านั้น** — ผูกที่แท็บ «สิทธิ์เซลล์-VDA» (ดู [Admin](#สิทธิ์เซลล์-vda-adminsystemvda-sales))
  ถ้ายังไม่ผูก จะขึ้นข้อความ "อีเมลนี้ยังไม่ได้ผูกกับรหัสเซลล์ — ให้แอดมินเพิ่มอีเมลที่แท็บ «สิทธิ์เซลล์-VDA» ก่อน"
- **รหัสเซลล์แต่ละรหัสดูแลคลัง VDA ไหน** มาจากทะเบียน VDA ขององค์กร (sync มาจากระบบกลาง) ไม่ได้ตั้งในระบบนี้

หน้าแรกหลังเข้าสู่ระบบ

| ตำแหน่ง | ไปที่ |
|---|---|
| เซลล์ | `/sales/orders` (หน้าตรวจสอบออเดอร์) |
| Admin ที่มีรหัสเซลล์ | `/sales/orders` — สลับไปหน้าตั้งค่าด้วยปุ่ม «ตั้งค่า» มุมขวาบน |
| Admin ที่ไม่มีรหัสเซลล์ | `/admin/stores/accounts` (บัญชีร้านค้า) |
| Creator | `/admin` (ศูนย์ Admin หมวด «ข้อมูล») |

หากเข้าสู่ระบบได้แต่ไม่พบออเดอร์ โปรดดู [ปัญหาที่พบบ่อย](#เซลล์เข้าสู่ระบบได้แต่ไม่พบออเดอร์)

### อายุของ session

ระบบจดจำการเข้าสู่ระบบไว้ **7 วัน** หากหมดอายุระหว่างการใช้งาน ระบบจะนำผู้ใช้กลับไปยัง
หน้าเข้าสู่ระบบพร้อมข้อความ "เซสชันหมดอายุแล้ว — กรุณาเข้าสู่ระบบใหม่เพื่อใช้งานต่อ"
กรณีนี้ไม่ใช่ความผิดปกติของระบบ เพียงเข้าสู่ระบบใหม่ ออกจากระบบได้ด้วยปุ่ม **«ออกจากระบบ»** มุมขวาบน

## ตำแหน่งผู้ใช้และสิทธิ์

| ตำแหน่ง | เข้าอย่างไร | ทำอะไรได้ |
|---|---|---|
| **ร้านค้า / VDA** | อีเมล + รหัสผ่าน | ดูสต็อก ส่งออเดอร์ ดูประวัติ ยืนยันรายการที่เซลล์แก้ ตั้ง MIN/MAX (ถ้าได้สิทธิ์) และหยุดสั่ง |
| **เซลล์** | Microsoft (อีเมลผูกกับรหัสเซลล์) | ตรวจ/แก้/อนุมัติออเดอร์ของคลังที่ตัวเองดูแล ออก PO จัดการสถานะ PO ส่ง PO เข้า ERP ดูโปร C4 |
| **Admin** | Microsoft (อีเมลที่ Creator เพิ่มไว้ในแท็บ «ผู้ดูแล») | หน้าตั้งค่าบางส่วน: บัญชีร้านค้า (ดู · อนุมัติ · เพิ่มบัญชี · รีเซ็ตรหัส) · โปร C4 ทุกคลัง (ดูอย่างเดียว) · สิทธิ์เซลล์-VDA (ดู · เพิ่มอีเมล) — ถ้ามีรหัสเซลล์ด้วยก็ใช้หน้าเซลล์ได้ตามรหัสนั้น |
| **Creator** | Microsoft (อีเมลที่ตั้งไว้ในไฟล์ตั้งค่าเซิร์ฟเวอร์ — ลบผ่านหน้าจอไม่ได้) | ทำได้ทุกอย่าง เห็นออเดอร์ทุกร้าน เข้ามุมมองทดสอบ และดูบันทึกการทำงาน |

## สำหรับร้านค้า / คลัง VDA

แถบเมนูด้านบนมี 3 แท็บ: **«สินค้า»** (`/stock`) · **«ประวัติสั่ง»** (`/history`) · **«จัดการ»** (`/manage`)
พร้อมกระดิ่งแจ้งเตือนและปุ่มสลับธีมสว่าง/มืด

### หน้าสต็อก `/stock`

หน้าจอหลักที่ใช้งานประจำวัน แสดงสินค้าทุกรายการในคลังพร้อมข้อมูลประกอบการตัดสินใจสั่งซื้อ
แถบสรุปด้านบนบอก **จำนวน SKU · คงเหลือรวม (หีบ) · มูลค่ารวม · CVD เฉลี่ย / กลุ่มโปร**

| คอลัมน์ | ความหมาย |
|---|---|
| SKU | รหัสสินค้าและบาร์โค้ด (เรียงจากน้อยไปมากเป็นค่าเริ่มต้น) |
| ชื่อสินค้า | ชื่อ พร้อมป้าย เช่น "ใหม่" · "ยังไม่มีในคลัง" · "หยุดสั่ง" · "ไม่ขาย 1 ด." |
| สต็อก (หีบ/เศษ) | จำนวนคงเหลือ แสดงเป็น "หีบ / เศษชิ้น" |
| ขายเฉลี่ย (30 วัน) | ปริมาณขายเฉลี่ยต่อวันของ 30 วันล่าสุด หน่วยหีบ — ตัวเดียวกับที่ใช้คิด CVD และจำนวนแนะนำ (ถ้าข้อมูล 30 วันว่างหรือเป็น 0 จะใช้ค่า 7 วันแทน) |
| CVD | จำนวนวันที่สินค้าคงเหลือเพียงพอต่อการขาย |
| MIN/MAX | เป้าหมายจำนวนวันที่ควรมีสินค้าคงคลัง (ตั้งที่หน้า «จัดการ») |
| ราคา/หีบ · ส่วนลด · สุทธิ/หีบ | ราคาตามตาราง C4 ณ วันปัจจุบัน |
| โปร | ขั้นโปรโมชันที่ได้รับ และของแถม |
| จำนวนสั่ง | ช่องกำหนดจำนวนที่ต้องการสั่ง (หน่วยหีบ) ระบบใส่จำนวนแนะนำไว้ให้ |
| CVD หลังสั่ง | ค่า CVD หลังจากสินค้าที่สั่งเข้าคลังแล้ว พร้อมสถานะธงสี |

**แท็บกรองด่วน** (แท็บที่ไม่มีรายการจะถูกซ่อน ยกเว้น «ทั้งหมด»)

| แท็บ | แสดงสินค้าที่ |
|---|---|
| ทั้งหมด | ทุกรายการในคลัง |
| ควรสั่ง | สต็อกต่ำกว่าเกณฑ์ ระบบแนะนำให้สั่งเพิ่ม |
| สต็อกวิกฤต | **ของจะหมดก่อนของรอบใหม่มาถึง** — สั่งอย่างเดียวอาจไม่ทัน ควรหาทางเสริม เช่น ยืมจากคลังอื่นหรือเร่งซัพพลายเออร์ |
| สินค้าใหม่ | เพิ่งเข้าระบบ |
| ไม่ขาย 1 เดือน | ไม่มียอดขายเลยใน 30 วัน — ควรพิจารณาหยุดสั่ง |
| ควรมีขาย | อยู่ในเป้าขายเดือนนี้ของเซลล์ แต่ร้านยังไม่เคยสต็อก — สั่งเพิ่มได้เลย |
| ค้างสต็อก | ไม่ขาย 30 วันและยังมีของค้างอยู่ (เงินจม) ต้องเร่งระบาย ไม่ใช่แค่หยุดสั่ง |
| หมุนช้า | ยังขายอยู่แต่ช้ามาก — ของที่มีพอขายเกิน 6 เท่าของ MAX |

> "สต็อกวิกฤต" เป็นชุดย่อยของ "ควรสั่ง" เสมอ — ถ้ารายการหนึ่งวิกฤต แปลว่าควรสั่งอยู่แล้ว
> แต่ที่ควรสั่งไม่ได้วิกฤตทุกตัว

**เครื่องมือบนแถบด้านบน**
- **ช่องค้นหา** ค้นด้วยชื่อ / รหัส / บาร์โค้ด / แบรนด์ — ขณะค้นหาจะค้น **ทั้งคลัง** ไม่จำกัดตามแท็บที่เปิด (ขึ้นป้าย «ค้นทั้งคลัง»)
- **«รายการ» / «โปรโมชั่น»** สลับมุมมอง: ตารางเต็มพร้อม CVD หรือจัดกลุ่มตามโปรโมชั่น
- **«ซ่อนของไม่ขาย 1 เดือน»** เอาสินค้าที่ไม่มียอดขายใน 30 วันออก ให้เหลือแต่ของที่ยังขาย
- **«กรอง»** เลือกแบรนด์ / กลุ่มสินค้า · **ปุ่มเรียงลำดับ** เลือกวิธีเรียง (หรือกดหัวคอลัมน์)
- **เมนูเพิ่มเติม (⋯)** «ส่งออกฟอร์มสั่ง» (Excel ตามตัวกรองและจำนวนบนจอ) · «ส่งออกเฉพาะที่เลือก» ·
  «ล้างจำนวนที่กรอกทั้งหมด» · «ล้างการเลือกทั้งหมด»

**ความหมายของธงสี**

| สี | ความหมาย |
|---|---|
| 🟢 เขียว | จำนวนเหมาะสม |
| 🟡 เหลือง | เกินเป้าหมายเล็กน้อย (เกิน MAX ไม่เกิน 4 วัน) อยู่ในเกณฑ์ที่ยอมรับได้ |
| 🔴 แดง | ควรตรวจสอบอีกครั้งก่อนส่งออเดอร์ |

> **ธงแดงไม่ได้ห้ามส่งออเดอร์** เป็นเพียงการขอให้ยืนยันอีกครั้ง โดยเฉพาะกรณีสินค้าหมด
> หรือกรณีที่ 1 หีบเป็นจำนวนขั้นต่ำ ซึ่งเป็นสถานการณ์ปกติ ไม่ใช่ความผิดพลาด

**การดูยอดขายย้อนหลังรายสินค้า** กดที่แถวสินค้าเพื่อกางกราฟยอดขาย (ยอดจากบิลจริง) เลือกช่วงเวลาได้
7 / 30 / 90 วัน สลับหน่วยหีบ/ชิ้นได้ พร้อมค่าเฉลี่ยต่อวัน · ต่อสัปดาห์ · ยอดรวม · อัตราการเปลี่ยนแปลงสัปดาห์นี้ (%)
และค่าเฉลี่ย 7 วันล่าสุด

> ปุ่ม **90 วัน อาจแสดงเป็นสีเทาและเลือกไม่ได้** ในกรณีที่ข้อมูลจริงยังสะสมไม่ครบตามช่วงเวลา
> ระบบจะเปิดให้เลือกโดยอัตโนมัติเมื่อข้อมูลเพียงพอ ทั้งนี้เพื่อไม่ให้แสดงกราฟที่เติมค่าศูนย์
> จนอาจทำให้เข้าใจผิดว่ายอดขายลดลง

**สัญญาณเตือนข้อมูลไม่เป็นปัจจุบัน** โดยปกติมุมขวาของแถบสรุปจะแสดง "ข้อมูล ณ <วันเวลา>" เป็นสีเทา
หากเปลี่ยนเป็น **"ข้อมูลค้าง" สีเหลืองหรือสีแดง** หมายความว่าข้อมูลไม่ได้รับการปรับปรุงเป็นเวลานานผิดปกติ
ค่า CVD และจำนวนที่ระบบแนะนำอาจไม่ตรงกับความเป็นจริง ให้กดปุ่ม **ตรวจข้อมูลใหม่** (ไอคอนลูกศรวน)
ข้าง ๆ หากยังไม่เปลี่ยนแปลงโปรดแจ้งแอดมิน

**การเลือกสินค้าที่จะสั่ง** ติ๊กแถว (หรือกรอกจำนวน) แล้วใช้แถบด้านล่าง: **«เลือกที่ควรสั่ง (N)»** ติ๊กทุกรายการที่ระบบแนะนำ
ตามตัวกรองปัจจุบัน · **«ล้างการเลือก»** · **«หยุดสั่ง»** · **«ตรวจสอบคำสั่ง»**

> จำนวนที่ระบบแนะนำ **หักสินค้าที่อยู่ระหว่างจัดส่งแล้ว** — ออเดอร์ที่ส่งไปก่อนหน้า
> และยังไม่ได้รับสินค้าจะไม่ทำให้ระบบแนะนำให้สั่งซ้ำ

### การหยุดสั่งสินค้า

ใช้กับสินค้าที่ไม่ต้องการให้ระบบแนะนำสั่งอีก (เช่น เลิกขาย ไม่มีที่เก็บ ขายไม่ดี)
1. ติ๊กสินค้าที่หน้าสต็อก (ในแท็บ «ไม่ขาย 1 เดือน» มีปุ่ม **«เลือกทั้งหมด (N)»** ให้เลือกรวดเดียว)
2. กด **«หยุดสั่ง»** ที่แถบล่าง → กรอกเหตุผล · วันเริ่ม (เว้นว่าง = เริ่มทันที) · วันสิ้นสุด หรือติ๊ก **«หยุดสั่งถาวร»**
3. กด **«ยืนยันหยุดสั่ง»** — ระบบแจ้งเซลล์ที่ดูแลร้านอัตโนมัติ

ยกเลิกได้ด้วยการกดป้าย "หยุดสั่ง" ในตาราง หรือที่หน้า «จัดการ» แท็บ «หยุดสั่ง»

### กด «ตรวจสอบคำสั่ง» แล้วมี 2 ขั้น

1. **ตรวจสินค้าที่มีโปรของแถม** (ขึ้นเมื่อมีสินค้าติดโปรของแถมในคำสั่ง) — ระบบเสนอปรับ
   จำนวนให้ลงขั้นโปร โดยปัดขึ้นเมื่อซื้อไปแล้วเกิน 30% ของขั้น (ขั้นที่ใหญ่กว่า 12 หีบ
   ใช้ 50%) ไม่ถึงเกณฑ์จะตัดเศษทิ้ง ทุกบรรทัดบอกจำนวนเดิมคู่กับจำนวนใหม่และของแถมที่จะได้ กด
   **«ใช้จำนวนเดิม»** เพื่อสั่งตามที่ตั้งไว้ได้เสมอ แล้วกด **«ถัดไป»**
2. **ยืนยันจำนวนที่สั่ง** — ตรวจว่าจำนวนเข้าเป้าหมาย MIN/MAX แก้ได้ในกล่องนี้เลย
   แล้วกด **«ตรวจสอบคำสั่ง»** เพื่อไปหน้า `/order` (กด «แก้ต่อ» เพื่อกลับไปแก้ที่หน้าสต็อก)

### หน้าตรวจสอบก่อนส่ง `/order`

- **แก้ไขจำนวนได้ที่หน้านี้โดยตรง** ไม่ต้องย้อนกลับไปยังหน้าสต็อก ทุกบรรทัดแสดง **ขนาดบรรจุ (ชิ้น/หีบ)**
- **ร้านค้าแก้ราคาเองไม่ได้** ใช้ราคาตามระบบ (C4) เสมอ หากต้องการราคาพิเศษให้แจ้งเซลล์
  ซึ่งแก้ราคาได้ในหน้าตรวจสอบออเดอร์
- **ไม่ต้องเลือกวันรับสินค้า** ระบบกำหนดวันส่งตามรอบปกติให้เอง
- **ชิปคำเตือนเหนือตาราง** (กดชิปเพื่อกรองให้เหลือเฉพาะรายการนั้น)

  | ชิป | ความหมาย |
  |---|---|
  | ไม่เข้าเป้า | จำนวนไม่เข้าเป้าหมาย MIN/MAX — ส่งได้ แต่อาจให้ยืนยันอีกครั้ง |
  | แถมไม่ลงตัว | ยอดรวมโปรกลุ่มไม่ลงขั้นของแถม — กด **«ปรับให้ลงตัวทั้งหมด»** ได้ |
  | สั่งซ้ำ | เคยสั่งสินค้ารายการเดียวกันไปแล้วภายใน 14 วัน — ตรวจสอบก่อนส่งซ้ำ |
  | ราคาต่าง | ราคาต่างจากราคาในระบบ — เซลล์จะเห็นธงให้ตรวจก่อนอนุมัติ |
  | โหลดโปรไม่สำเร็จ | ยังคำนวณส่วนลดโปรกลุ่มไม่ได้ — ลองแก้จำนวนอีกครั้งให้ระบบลองใหม่ |

- สินค้าในกลุ่มโปรโมชันเดียวกันจะจัดเรียงติดกันพร้อมยอดรวมของกลุ่ม เพื่อให้เห็นว่าใกล้ถึงขั้นโปรโมชันหรือไม่
- ปุ่มอื่น: **«กลับหน้าสต็อก»** · **«รีเซ็ตเป็นจำนวนแนะนำ»** · ติ๊กแถวแล้วกด **«ลบ N รายการ»** เพื่อเอาออกจากคำสั่ง

เลือก **«ยืนยันส่ง»** เพื่อส่งออเดอร์ไปยังเซลล์เพื่อตรวจสอบ (ถ้ามีรายการไม่เข้าเป้า จะมีกล่องให้กด «ส่งออเดอร์» ยืนยันอีกครั้ง)
เมื่อส่งสำเร็จจะขึ้น "ส่งออเดอร์แล้ว"

### หน้าประวัติ `/history` (แท็บ «ประวัติสั่ง»)

- ข้อมูลสรุป 5 รายการ ได้แก่ ออเดอร์ทั้งหมด · รออนุมัติ · อนุมัติแล้ว · รวมที่สั่ง (หีบ) · มูลค่ารวม
- กรองตามสถานะ (ทั้งหมด / รออนุมัติ / อนุมัติแล้ว / ปฏิเสธ) และช่วงเวลา (7 / 30 / 90 วัน / ทั้งหมด)
  ค้นหาด้วยรหัส / ชื่อสินค้า / เลข PO ได้ · แสดง 100 ออเดอร์ล่าสุด
- ขยายรายการเพื่อดู **ลำดับเหตุการณ์** (ส่งออเดอร์ → อนุมัติ/ปฏิเสธ → ออก PO) · **เลข PO พร้อมสถานะของ PO**
  (ใช้อ้างอิงเวลาตามของ) · จำนวนที่ระบบแนะนำคู่กับที่สั่งจริง · ราคาต่อบรรทัด · **ของแถมที่ควรได้**
  และเหตุผลกรณีถูกปฏิเสธ
- **«สั่งซ้ำ»** นำจำนวนเดิมกลับไปกำหนดที่หน้าสต็อก (สินค้าที่ไม่มีในสต็อกวันนี้จะไม่ถูกเลือก)
- **«ยกเลิกออเดอร์»** ทำได้เฉพาะรายการที่รออนุมัติและยังไม่ได้ออก PO — ออเดอร์จะถูกลบ กู้คืนไม่ได้ และเซลล์จะได้รับแจ้ง

#### รายการที่รอร้านยืนยัน

ออเดอร์ที่มีป้ายสีเหลือง **"รอคุณยืนยัน N รายการ"** แปลว่าพนักงานทำอย่างใดอย่างหนึ่งต่อไปนี้
และ **ต้องรอร้านตอบก่อน** พนักงานจึงจะอนุมัติออเดอร์ทั้งใบได้

| กรณี | ข้อความในรายการ | กด «ยืนยัน» | กด «ปฏิเสธ» |
|---|---|---|---|
| พนักงานเพิ่มจำนวนเกินที่ร้านสั่ง | "พนักงานขอเพิ่มจำนวน … เป็น N หีบ — ยืนยันไหม?" | ใช้จำนวนใหม่ | จำนวนกลับเป็นเท่าที่ร้านสั่งไว้ |
| พนักงานเพิ่มสินค้าที่ร้านไม่ได้สั่ง | "พนักงานเพิ่มสินค้าใหม่ … N หีบ เข้าออเดอร์นี้ — ยืนยันไหม?" | รับสินค้านั้นเข้าออเดอร์ | **นำสินค้านั้นออกจากออเดอร์** |

> การลดจำนวนไม่ต้องรอร้านยืนยัน ร้านจะได้รับแจ้งเตือน "แก้จำนวน" เพื่อทราบเท่านั้น

### กระดิ่งแจ้งเตือนของร้าน (มุมขวาบนทุกหน้า)

- เลขแดงบนกระดิ่ง = จำนวนที่ยังไม่อ่าน · **กดเปิดกระดิ่ง = อ่านแล้ว** เลขแดงหายทันที (ไม่ต้องกดอ่านทีละรายการ)
- มีแจ้งเตือนใหม่ระหว่างใช้งานจะเด้งขึ้นมุมจอ · กด «ดูทั้งหมด N รายการ» เพื่อดูของเก่า
- **กดที่แจ้งเตือนเพื่อเปิดออเดอร์ใบนั้น** ระบบจะพามาหน้าประวัติ กางรายการ และเลื่อนไปที่ใบนั้นให้

| ป้าย | เกิดเมื่อ |
|---|---|
| อนุมัติ | เซลล์อนุมัติ — ขึ้นเป็นแจ้งเตือนเดียว **"อนุมัติออเดอร์และออก PO แล้ว"** พร้อมเลข PO (หลายใบจะบอกยอดรายใบ) |
| ปฏิเสธ / ปฏิเสธรายการ | ปฏิเสธทั้งใบ หรือรายการเดียว พร้อมเหตุผล (ถ้าเซลล์ระบุ) |
| แก้ราคา / แก้จำนวน | เซลล์แก้ราคาหรือลดจำนวน |
| รอยืนยันเพิ่มจำนวน / รอยืนยันสินค้าใหม่ | เซลล์เพิ่มจำนวนหรือเพิ่มสินค้า — ต้องไปตอบที่หน้าประวัติ |
| แยกออเดอร์ | เซลล์อนุมัติเฉพาะบางรายการ รายการที่เหลือย้ายไปรอในออเดอร์ใบใหม่ |
| เคลียร์รายการ / ลบออเดอร์ | เซลล์เคลียร์สินค้าหรือลบออเดอร์ (เช่น เคลียร์สิ้นเดือน) |
| ยกเลิก PO / รับของแล้ว / PO กลับมาใช้งาน | เซลล์เปลี่ยนสถานะ PO |
| เข้า ERP แล้ว | PO ถูกส่งเข้าระบบ ERP แล้ว |
| เปลี่ยนเลข PO | PO เดิมถูกแทนด้วยเลขใหม่ (รายการเหมือนเดิม) — ใช้เลขใหม่อ้างอิงตอนรับของ |

### หน้าจัดการ `/manage` (แท็บ «จัดการ»)

มี 3 แท็บย่อย
- **«ตั้ง MIN / MAX»** กำหนดจำนวนวันเป้าหมาย **ตามแบรนด์** (ค่าเริ่มต้นตามที่หน้าจอบอก) กดดูรายสินค้าเพื่อตั้งค่าพิเศษรายตัว
  หรือใช้ «ตั้งค่าหลายแบรนด์พร้อมกัน» แบรนด์ที่มีสินค้าใหม่จะถูกจัดขึ้นบนสุด
  — **แก้ได้เฉพาะบัญชีที่ Creator ให้สิทธิ์ "จัดการ min/max"** บัญชีอื่นจะเห็นข้อความ "บัญชีนี้ดูได้อย่างเดียว"
- **«หยุดสั่ง»** รายการสินค้าที่หยุดสั่งอยู่ ค้นหา/เรียงได้ แก้เหตุผลหรือช่วงวัน หรือยกเลิกหยุดสั่ง (แจ้งเซลล์อัตโนมัติ)
- **«รหัสผ่าน»** เปลี่ยนรหัสผ่านเอง (ต้องรู้รหัสเดิม รหัสใหม่อย่างน้อย 8 ตัวอักษร) หรือถ้าจำรหัสเดิมไม่ได้
  กด **«แจ้งแอดมินให้รีเซ็ตรหัส»**

## สำหรับเซลล์

แถบเมนูของเซลล์มี 4 แท็บ: **«ภาพรวม»** (`/sales`) · **«ออเดอร์»** (`/sales/orders`) · **«ใบสั่งซื้อ (PO)»** (`/sales/po`)
· **«โปรโมชั่น»** (`/sales/promotions`) — แท็บ «ออเดอร์» มีตัวเลขจำนวนออเดอร์รอตรวจ และ ⚠ จำนวนออเดอร์ที่ราคาไม่ตรงระบบ

### หน้าภาพรวม `/sales`

แสดงสถานการณ์ภาพรวมก่อนเริ่มปฏิบัติงาน

| การ์ดข้อมูล | ความหมาย |
|---|---|
| ออเดอร์รอตรวจ | จำนวนออเดอร์ที่รอการตรวจสอบ เลือกเพื่อเข้าสู่หน้าตรวจสอบได้ทันที |
| มีราคาไม่ตรงระบบ | ออเดอร์ที่มีบรรทัดซึ่งราคาต่างจากระบบ ควรตรวจสอบก่อน (ร้านค้ากำหนดมาเอง หรือพนักงานขายแก้ในหน้าตรวจสอบก็นับ) |
| อัตราอนุมัติ (30 วัน) | สัดส่วนการอนุมัติจากออเดอร์ที่ตัดสินแล้ว |
| ตัดสินแล้ว (30 วัน) | จำนวนออเดอร์ที่ดำเนินการเสร็จสิ้น |

ส่วนด้านล่างแสดง **ร้านที่ติดธงแดงมากที่สุด** ซึ่งควรติดต่อสอบถาม และ **ตัดสินล่าสุด**

> อัตราการอนุมัติ **ไม่รวมออเดอร์ที่ร้านค้ายกเลิกเอง** เนื่องจากออเดอร์ที่ร้านค้ายกเลิก
> จะถูกลบออกจากระบบ จึงไม่เคยถูกนับรวมตั้งแต่ต้น

### หน้าตรวจสอบออเดอร์ `/sales/orders`

ด้านซ้ายแสดงรายการออเดอร์ ด้านขวาแสดงรายละเอียดของใบที่เลือก

**ตัวกรองด้านซ้าย**
- สถานะ: **«รออนุมัติ» · «อนุมัติแล้ว» · «ปฏิเสธ» · «ทั้งหมด»**
- **«รหัสเซลล์»** (ขึ้นเมื่ออีเมลเดียวถือหลายรหัส) เลือกรหัสเพื่อดู VDA ที่รหัสนั้นดูแล
- **«ดูออเดอร์ทุก VDA ของฉัน (N)»** ดูทุกคลังของทุกรหัสที่ถือ ไม่ต้องสลับรหัส
- **VDA** เลือกคลัง (หรือ "ทุก VDA ที่ดูแล") · **เรียงตาม** วันที่ / ร้าน
- การ์ดออเดอร์แต่ละใบบอกจำนวน SKU วันเวลาที่ส่ง ป้าย **"ราคาต่างระบบ N"** และ **"ธงแดง N"**

**การตรวจสอบทีละรายการ** ปรับจำนวนและราคารายบรรทัด → จัดกลุ่ม PO หากต้องแบ่งใบ → อนุมัติ

ตารางแบ่งคอลัมน์ **รายการสินค้า · โปร · หีบ · ราคา/หีบ · มูลค่า** (ราคาและมูลค่าคิดจากราคาที่บันทึกไว้ตอนร้านส่ง —
ตัวเดียวกับที่ขึ้นเอกสาร PO ทุกจุดบนหน้าจึงเป็นเลขเดียวกัน) แถวละบรรทัดหลัก (รหัส + ชื่อ) ป้ายสถานะอยู่บรรทัดรอง
แถวที่ติ๊กจะเป็นสีเขียวอ่อน แถว 0 หีบจะจางลง · แถบปุ่มอนุมัติบอก **"จะออก PO N รายการ · X หีบ · มูลค่า Y บาท"**
ก่อนกดทุกครั้ง · แก้ราคาได้ด้วยไอคอนดินสอข้างราคา/หีบ · ปฏิเสธรายการด้วยไอคอน ⊗ ท้ายแถว
· บนจอคอม **ตารางยาวครบทุกรายการ** เลื่อนทั้งหน้า (ไม่ต้องเลื่อนในกล่องเล็ก) — หัวตาราง แถบปุ่มอนุมัติ
และรายการออเดอร์ทางซ้ายติดจอไว้ระหว่างเลื่อน · **«ขยายตาราง»** ซ่อนรายการออเดอร์ทางซ้ายให้ตารางกว้างเต็มจอ
กด «ย่อตาราง» เพื่อกลับ (ระบบจำโหมดที่เลือกไว้ในเครื่อง)

- **ตัวกรองในตาราง** «ทุกรายการ (N)» / «เฉพาะได้โปร (N)» และเมนู **"กลุ่มสินค้า"**
- **การปรับจำนวน** ใช้ปุ่ม − / + หรือพิมพ์ตัวเลขในช่องแล้วกด Enter · ใต้ช่องบอกจำนวน "แนะนำ" ไว้ให้เทียบ
  - **ลดจำนวน** มีผลทันที
  - **เพิ่มเกินที่ร้านสั่ง** รายการจะขึ้นป้าย **"⚠ รอร้านยืนยันเพิ่มจำนวน"** และต้องรอร้านตอบก่อน
  - **จำนวนต่ำสุดคือ 1 หีบ** พิมพ์ 0 ไม่ได้ (ระบบคืนค่าเดิม) — ถ้าไม่ต้องการรายการนั้นให้ใช้ «ปฏิเสธ»
- **ปฏิเสธรายการเดียว** กดไอคอน ⊗ ที่บรรทัดนั้น เลือกเหตุผล (สต็อกยังพอ / ราคาไม่ถูกต้อง / เกิน MAX / รอรอบส่งถัดไป)
  หรือพิมพ์เอง (ไม่บังคับ) แล้วกด «ยืนยันปฏิเสธ» รายการจะเป็น 0 หีบพร้อมป้าย "ปฏิเสธแล้ว" และร้านได้รับแจ้งพร้อมเหตุผล
- **เพิ่มสินค้าที่ร้านไม่ได้สั่ง** กด **«เพิ่มสินค้า»** (ปุ่มสีเขียวขวาบนของตาราง) → พิมพ์รหัส บาร์โค้ด ชื่อ หรือแบรนด์
  (ค้นจากสินค้าทั้งหมดในระบบ ไม่จำกัดเฉพาะที่ร้านมีสต็อก) → เลือกสินค้า → กรอกจำนวน (หีบ) →
  «เพิ่มเข้าออเดอร์» รายการใหม่จะขึ้นป้าย **"⚠ รอร้านยืนยันสินค้าใหม่"** ร้านต้องไปยืนยันที่หน้า `/history`
  - ใช้ราคา C4 เป็นค่าตั้งต้น แก้ราคาภายหลังได้ในตารางตามปกติ
  - สินค้าที่มีอยู่ในออเดอร์แล้วเพิ่มซ้ำไม่ได้ ให้แก้จำนวนที่บรรทัดเดิมแทน
  - สินค้าที่อยู่กลุ่มโปรเดียวกับของเดิม ระบบคิดยอดรวมกลุ่มและส่วนลดขั้นบันไดใหม่ให้ทั้งกลุ่ม
    หากร้านปฏิเสธ ระบบนำสินค้าออกและคิดโปรของรายการที่เหลือกลับเป็นเหมือนเดิม
- **ย้ายทั้งกลุ่มสินค้าไป PO เดียวกัน** เลือกกลุ่มจากเมนู "กลุ่มสินค้า" แล้วกด **«เลือกทั้งหมดที่กรองอยู่ (N)»**
- ป้าย **"ไม่มีเป้า"** หมายถึงสินค้านั้นไม่อยู่ในเป้าขายของเซลล์เดือนนี้
- ร้านค้าจะได้รับการแจ้งเตือนทุกครั้งที่มีการแก้ไขจำนวนหรือราคา

> **อนุมัติไม่ได้ขณะมีรายการรอร้านยืนยัน** ปุ่มอนุมัติจะเป็นสีจาง พร้อมข้อความ
> "มี N รายการที่รอร้านยืนยัน — อนุมัติได้เมื่อร้านตอบครบแล้ว" ออเดอร์ลักษณะนี้จะไม่ถูกเลือกโดย
> "เลือกทั้งหมดที่ไม่มีธงแดง" ด้วย

**อนุมัติทั้งใบ** กด **«อนุมัติ → ออก PO»** (ถ้าแบ่งไว้หลายใบ ปุ่มจะเป็น «อนุมัติ → ออก N PO»)
ถ้ามีรายการราคาไม่ตรงระบบ จะมีกล่องให้ตรวจแล้วกด «อนุมัติและออก PO» อีกครั้ง — **ออกเลข PO แล้วย้อนกลับไม่ได้**

**ปฏิเสธทั้งใบ** กด **«ปฏิเสธ»** ที่แถบปุ่ม เลือกเหตุผลหรือพิมพ์เอง (ไม่บังคับ) แล้วกด «ยืนยันปฏิเสธ»

**อนุมัติเฉพาะบางรายการ** ติ๊กรายการที่ต้องการ ปุ่มจะเปลี่ยนเป็น **«อนุมัติเฉพาะที่เลือก (N) → ออก PO»**
พร้อมข้อความ "เลือกไว้ N จาก M รายการ" กดแล้วยืนยันในกล่อง ระบบจะ
- ออก PO ให้เฉพาะรายการที่ติ๊ก ใบนี้เปลี่ยนเป็น "อนุมัติแล้ว"
- **ย้ายรายการที่ไม่ได้ติ๊กไปเป็นออเดอร์ใบใหม่ของร้านเดิม สถานะรออนุมัติ** (วันที่สั่งเดิม) มาอนุมัติทีหลังได้
  ร้านได้รับแจ้ง "แยกออเดอร์"
- **สินค้าในกลุ่มโปรที่รวมยอดกันต้องอยู่ด้วยกัน** ติ๊กตัวหนึ่ง ระบบติ๊กตัวอื่นในกลุ่มให้เอง
  เพื่อไม่ให้ส่วนลดขั้นบันไดผิด
- ติ๊กครบทุกรายการหรือไม่ติ๊กเลย = อนุมัติทั้งใบตามปกติ
- รายการที่รอร้านยืนยันแต่ไม่ได้ติ๊ก จะย้ายไปรอในใบใหม่ ไม่กันการอนุมัติรอบนี้

**การแบ่ง PO อัตโนมัติ** ระบบเสนอให้ก่อน และพนักงานปรับได้ก่อนอนุมัติ (ติ๊กรายการ แล้วกด
«ย้าย N รายการมา PO-X» หรือ «เพิ่มกลุ่มใหม่ (PO-X)») · ถ้าแบ่งไว้หลายใบ กด **«รวมเป็น PO เดียว»** มุมขวาของแผงแบ่ง PO
เพื่อรวมทุกรายการกลับเป็นใบเดียวในคลิกเดียว

| ใบ | รายการที่อยู่ |
|---|---|
| PO-A | ราคาตรง C4 และจำนวนตามที่ร้านสั่ง |
| PO-B | ราคาไม่ตรง C4 |
| PO-C | จำนวนต่างจากที่ร้านสั่ง (รวมสินค้าที่พนักงานเพิ่มเอง) |
| PO-D | ทั้งราคาไม่ตรง C4 และจำนวนต่างจากที่ร้านสั่ง |

> **สินค้าในกลุ่มโปรที่รวมยอดกันต้องอยู่ PO ใบเดียวกัน** ระบบเสนอให้อยู่ด้วยกันเสมอ ถ้าย้ายแยกกันเอง
> แผงแบ่ง PO จะขึ้นข้อความสีแดงและอนุมัติไม่ได้จนกว่าจะย้ายกลับมาอยู่ใบเดียวกัน

> ⚠️ **สินค้าที่อยู่ในกลุ่มโปรโมชัน** หากถูกปฏิเสธ (เหลือ 0 หีบ) รายการจะยังคงปรากฏในเอกสาร PO
> พร้อมหมายเหตุ เนื่องจากการนำออกจะทำให้ส่วนลดของสินค้ารายการอื่นในกลุ่มคลาดเคลื่อน
> กรุณาตรวจสอบขั้นโปรโมชันอีกครั้งก่อนส่ง

**การอนุมัติหลายใบพร้อมกัน** ติ๊กช่องมุมการ์ดออเดอร์หลายใบ หรือใช้ปุ่ม
**«เลือกทั้งหมดที่ไม่มีธงแดง»** แล้วกด **«อนุมัติ N ใบ»** → «อนุมัติทั้งหมด» ระบบจะดำเนินการทีละใบตามลำดับ
พร้อมสรุปผลว่าใบใดสำเร็จและใบใดไม่สำเร็จพร้อมสาเหตุ

> ออเดอร์ที่การแบ่ง PO ไม่ผ่านเงื่อนไข เช่น กลุ่มโปรโมชันถูกแยกคนละใบ จะไม่ถูกนับรวมในการอนุมัติหลายใบ

> หากผู้ใช้งานท่านอื่นอนุมัติออเดอร์ใบเดียวกันพร้อมกัน **ระบบจะบันทึกให้สำเร็จเพียงคนเดียว**
> อีกฝ่ายจะได้รับข้อความแจ้งว่าออเดอร์ถูกตัดสินไปแล้ว กรณีนี้ไม่ใช่ข้อผิดพลาด
> แต่เป็นกลไกป้องกันการออกเลขที่ PO ซ้ำซ้อน

**ลบออเดอร์** กดปุ่ม **«ลบ»** ที่หัวรายละเอียดออเดอร์ (ลบได้ทุกสถานะ) หรือติ๊กหลายใบแล้วกด «ลบ N ใบ»
ออเดอร์ รายการสินค้า **PO ที่ออกไปแล้ว** ประวัติที่ร้านเห็น และแจ้งเตือนเดิมจะถูกลบทั้งหมด ย้อนกลับไม่ได้
เลือกได้ว่าจะติ๊ก «แจ้งให้ร้านทราบว่าถูกลบ» หรือไม่ · PO ที่ส่งเข้า ERP แล้ว (หรือผลไม่ชัดเจน) ลบไม่ได้
· ทุกการลบถูกจดในบันทึกการทำงาน

**เคลียร์ออเดอร์สิ้นเดือน** กดปุ่มสีแดง **«เคลียร์สิ้นเดือน»** ด้านขวาเหนือรายการออเดอร์ (ระบบสลับตัวกรองเป็น
«รออนุมัติ» ให้เอง) แล้วเลือก
- **เคลียร์ทั้งใบ** รายการออเดอร์รออนุมัติที่แสดงอยู่จะถูกติ๊กไว้ทั้งหมด เอาติ๊กออกได้ทีละใบ
  เลือกได้ว่าจะแจ้งร้านหรือไม่
- **เคลียร์เฉพาะสินค้า** กรอกรหัสสินค้า ระบบบอกว่าพบในกี่ใบ แล้วลบสินค้านั้นออกจากทุกออเดอร์
  ที่ยังรออนุมัติที่ท่านดูแล (ไม่ใช่เฉพาะที่กรองอยู่) ถ้าใบไหนไม่เหลือรายการเลย ใบนั้นจะถูกลบไปด้วย ·
  ส่วนลดโปรกลุ่มของสินค้าที่เหลือในใบคิดใหม่ให้ตามยอดจริง · ร้านได้รับแจ้ง "เคลียร์รายการ" (เลือกไม่แจ้งได้)
- ทั้งสองแบบ **ข้ามใบที่ออก PO แล้วโดยอัตโนมัติ** และย้อนกลับไม่ได้

### หน้าใบสั่งซื้อ `/sales/po`

- การ์ดสรุป: PO ทั้งหมด · รวม (หีบ) · มูลค่ารวม · ราคาไม่ตรง C4 (คิดจากผลกรองทั้งหมด)
- ค้นหาด้วยเลขที่ PO รหัสคลัง หรือชื่อร้านค้า (ค้นหาจากข้อมูลทั้งหมด ไม่จำกัดเฉพาะหน้าที่แสดงอยู่)
- กรองตามประเภทราคา (ทั้งหมด / ตรง C4 / ไม่ตรง C4) · **สถานะ** · **«ทุก VDA ของฉัน»** · คลัง · ช่วงวันที่ออก · «ล้างตัวกรอง»
- ป้ายในแถว: **"แบ่ง N ใบ"** (ออเดอร์นี้ออกหลาย PO) · **"ต้องตรวจ ERP"** · **"รอขอเลขใหม่"** · **"ถูกแทนที่"**
- ปุ่มท้ายแถว: **Excel** (ไฟล์ PO ใบนั้น) · **JSON** (ข้อมูลดิบที่ส่งต่อฝ่ายจัดซื้อ) · ไอคอนถังขยะ (ลบ PO พร้อมออเดอร์ต้นทาง)
- เลือกหลายใบเพื่อ **«ดาวน์โหลด Excel รวม»** เป็นไฟล์เดียว (ชีตสรุปและชีตรายใบ ครั้งละไม่เกิน 50 ใบ) หรือ «ลบ N ใบ»
- กดแถวเพื่อเปิด **รายละเอียด PO** (รายการ ราคา ที่มาราคา โปร ของแถมที่ต้องส่ง ยอดรวม VAT) พร้อมปุ่ม **«พิมพ์»**

**สถานะ PO** เปลี่ยนได้จากช่องสถานะในตารางโดยตรง

| สถานะ | ความหมาย | ใครตั้ง |
|---|---|---|
| ออกแล้ว | ออกเลข PO แล้ว รอส่งให้ซัพพลายเออร์ | ระบบ (ค่าเริ่มต้น) / เลือกเองได้ |
| ส่งซัพแล้ว | ส่งใบสั่งซื้อให้ซัพพลายเออร์แล้ว รอของ | เลือกเอง |
| กำลังส่ง ERP | กำลังยิงเข้า ERP อยู่ — อย่ากดซ้ำ | **ระบบตั้งให้เอง** |
| เข้า ERP แล้ว | ปลายทางรับเข้าระบบแล้ว (ยังไม่ได้แปลว่าออกบิลแล้ว) | **ระบบตั้งให้เอง** |
| ERP ไม่ตอบ — รอตรวจ | ส่งไปแล้วแต่ไม่รู้ผล (ปลายทางไม่ตอบ / เน็ตหลุด) ใบนั้นอาจเข้า ERP ไปแล้ว | **ระบบตั้งให้เอง** |
| รับของแล้ว | ของเข้าคลังครบแล้ว | เลือกเอง |
| ยกเลิก | ยกเลิกใบนี้ ไม่ต้องส่งของ | เลือกเอง |

- **ตัวเลือกที่ระบบจะไม่รับจะเป็นสีเทาเลือกไม่ได้** ได้แก่ สถานะ 3 ตัวที่ระบบตั้งเอง · ทุกตัวเลือกขณะ «กำลังส่ง ERP» ·
  และใบที่เข้า ERP แล้ว (หรือ «ERP ไม่ตอบ — รอตรวจ») **เปลี่ยนได้แค่เป็น «รับของแล้ว»** — ยกเลิก ลบ หรือถอยสถานะไม่ได้
  ถ้าต้องยกเลิกจริงต้องยกเลิกในระบบ ERP ก่อน แล้วแจ้งผู้ดูแลระบบ
- ใบที่เคยยกเลิกแล้วเปลี่ยนกลับเป็นสถานะอื่น ร้านจะได้แจ้งเตือน "PO กลับมาใช้งาน"

> **การเปลี่ยนสถานะมีผลต่อร้านค้าทันที** เมื่อกำหนดสถานะเป็น "ยกเลิก" หรือ "รับของแล้ว"
> ร้านค้าจะได้รับการแจ้งเตือน และระบบจะหยุดกันไม่ให้ร้านค้าสั่งสินค้ารายการนั้นซ้ำ
> (ก่อนหน้านี้ร้านค้าไม่ได้รับแจ้งเมื่อ PO ถูกยกเลิก และไม่สามารถสั่งสินค้าใหม่ได้เป็นเวลา 3 วัน)

#### ส่ง PO เข้า ERP

อยู่ในรายละเอียด PO ส่วน **«ข้อมูลที่จะส่งเข้า ERP»**
1. ระบบตรวจว่าข้อมูลครบตามที่ปลายทางต้องการ — ถ้าไม่ครบจะขึ้น "ยังส่งไม่ได้ N เรื่อง" พร้อมรายการที่ต้องแก้
2. กด **«ส่งเข้า ERP»** → กล่องยืนยัน "ยืนยันส่ง <เลข PO> เข้า ERP?" → **«ส่งเลย»**
   **ย้อนกลับไม่ได้** — ปลายทางล็อกเลขใบนี้ไว้ 6 เดือนทันทีที่รับ
3. ผลที่เป็นไปได้
   - สำเร็จ → สถานะ «เข้า ERP แล้ว» ร้านได้แจ้งเตือน ส่งซ้ำไม่ได้อีก
   - **ERP ปฏิเสธ** → ส่งซ้ำด้วยเลขเดิมไม่ได้ ต้องกด **«ขอเลขใหม่แล้วลองส่งอีกครั้ง»** (ใบเดิมขึ้นป้าย "ถูกแทนที่"
     ร้านได้แจ้งเตือน "เปลี่ยนเลข PO")
   - **ไม่รู้ผล** → สถานะ «ERP ไม่ตอบ — รอตรวจ» (ดูด้านล่าง)
   - ส่งไม่สำเร็จ เซลล์ทุกคนที่ดูแลคลังนั้นจะได้แจ้งเตือน "ส่ง ERP ไม่สำเร็จ" ที่กระดิ่ง
4. ถ้าปุ่มเป็นสีจาง ให้เอาเมาส์ชี้ที่ปุ่มเพื่อดูเหตุผล (เช่น ข้อมูลยังไม่ครบ หรือระบบยังไม่เปิดการส่ง)

**ใบ «ERP ไม่ตอบ — รอตรวจ»** ใบนั้นอาจเข้า ERP ไปแล้ว **ห้ามส่งซ้ำหรือขอเลขใหม่เอง** ให้ตรวจกับทีม ERP ก่อน
แล้วเปิดรายละเอียด PO ใบนั้น ในกล่องแดง «ยิงครั้งก่อนไม่ชัดเจน…» ส่วน "ตรวจกับทีม ERP แล้ว?" กดปุ่มตามผลที่ได้
แล้วพิมพ์ว่าตรวจกับใคร / เมื่อไหร่ (ต้องกรอก) ก่อนกด **«บันทึกผลการตรวจ»**
- **«มีใบนี้ใน ERP แล้ว»** → ใบเปลี่ยนเป็น «เข้า ERP แล้ว» ร้านได้แจ้งเตือน และส่งซ้ำไม่ได้อีก
- **«ไม่มีใน ERP — ส่งใหม่ได้»** → ใบกลับเป็น «ออกแล้ว» กดส่งเข้า ERP ได้อีกครั้ง **ด้วยเลขเดิม**
  (ถ้าที่จริงเข้าไปแล้ว ERP จะตีกลับเพราะเลขซ้ำ ไม่เกิดออเดอร์ซ้อน — ปลอดภัยกว่าขอเลขใหม่)
- ทุกครั้งถูกจดใน «ระบบ › บันทึกการทำงาน» พร้อมข้อความ error เดิมและบันทึกที่พิมพ์

### หน้าโปรโมชั่น `/sales/promotions`

ดูโปร C4 ของเดือนปัจจุบัน **แยกตามคลัง** — เลือกคลังจากรายการด้านบน หรือดูรวมทุกคลัง
สลับดูเป็นกลุ่มโปรหรือรายสินค้า กรองตามประเภทสิทธิประโยชน์ (ส่วนลดบาท / ส่วนลด % / ของแถม / ...)
กรองตาม **แบรนด์ แล้วแคบลงด้วยกลุ่มสินค้า** และส่งออก Excel ได้ — ไฟล์ใช้ตัวกรองคลัง/แบรนด์/กลุ่มสินค้าเดียวกับบนจอ
(มุมมองกลุ่มโปรแสดงสมาชิกครบทั้งกลุ่ม ถ้ามีสินค้าตรงตัวกรองอย่างน้อย 1 ตัว เพราะเงื่อนไขโปรนับยอดรวมทั้งกลุ่ม)

> โปรของแต่ละคลังไม่เหมือนกัน เพราะผูกกับภูมิภาคของคลังนั้น การเลือกคลังก่อนดู
> จึงสำคัญ ไม่งั้นอาจแจ้งร้านด้วยโปรที่คลังนั้นไม่ได้รับจริง
> หน้านี้แสดงโปร **ทั้งเดือน** ส่วนหน้าสต็อกและหน้าออเดอร์ของร้านแสดงเฉพาะที่ใช้ได้วันนี้

ท่านจะเห็นเฉพาะคลังที่ตัวเองดูแล ส่วน Admin / Creator เลือกดูได้ทุกคลังที่ `/admin/promotions/c4`

### กระดิ่งแจ้งเตือนของเซลล์ (มุมขวาบนทุกหน้าเซลล์)

แทนแท็บ "การแจ้งเตือน" เดิม — เลขแดงบนกระดิ่งคือจำนวนที่ยังไม่อ่าน

- **ออเดอร์ใหม่ · ร้านยกเลิก · คำตอบของร้าน** ต่อรายการที่รอยืนยัน (ร้านยืนยัน/ปฏิเสธเพิ่มจำนวน, ร้านรับ/ไม่รับสินค้าที่เพิ่ม)
  · **ส่ง ERP ไม่สำเร็จ** · **ยกเลิกหยุดสั่ง**
- **กดที่แจ้งเตือนเพื่อเปิดใบออเดอร์นั้น** ในหน้าตรวจสอบออเดอร์ (สลับตัวกรองให้เอง) ถ้าออเดอร์ถูกลบแล้วจะบอก "ออเดอร์นี้ถูกลบไปแล้ว"
- **กดเปิดกระดิ่ง = รับทราบแจ้งเตือนออเดอร์ทั้งหมด** · มีแจ้งเตือนใหม่ระหว่างใช้งานจะเด้งขึ้นมุมจอ
- **รายการหยุดสั่งจากร้านไม่ถูกรับทราบให้อัตโนมัติ** — กระดิ่งบอก "ร้านแจ้งหยุดสั่ง N รายการ รอรับทราบ →"
  แล้วพาไปหน้ารวม `/sales/notifications` (ลิงก์ «ดูหน้ารวม + หยุดสั่ง →» ท้ายกระดิ่ง) ซึ่งกดรับทราบทีละรายการ
  หรือ «รับทราบทั้งหมด» ได้ (หน้ารวมมีทั้งส่วน "ออเดอร์จากร้าน" และ "รายการหยุดสั่ง")

## สำหรับ Admin

Admin คืออีเมลที่ Creator เพิ่มไว้ในแท็บ «ผู้ดูแล» เข้าหน้าตั้งค่า (`/admin`) ได้ **เฉพาะ 3 แท็บ**

| หมวด | แท็บ | Admin ทำอะไรได้ |
|---|---|---|
| ร้านค้า | «บัญชีร้านค้า» `/admin/stores/accounts` | ดูคำขอที่รออนุมัติและร้านที่อนุมัติแล้ว · อนุมัติ · เพิ่มบัญชี · รีเซ็ตรหัส / ออกรหัสตั้งค่าใหม่ |
| โปรโมชั่น | «โปร C4 เดือนนี้» `/admin/promotions/c4` | ดูโปรทุกคลัง เลือกดูรายคลัง และ «ส่งออก Excel» |
| ระบบ | «สิทธิ์เซลล์-VDA» `/admin/system/vda-sales` | ดูตาราง และ **เพิ่ม** อีเมลให้รหัสเซลล์ (เอาออกไม่ได้) |

- **Admin ที่มีรหัสเซลล์** จะถูกพาไปหน้า `/sales/orders` หลังเข้าสู่ระบบ มีปุ่ม **«ตั้งค่า»** มุมขวาบน
  (พร้อมตัวเลขคำขอร้านค้าที่รออยู่ — ทั้งสมัครใหม่และขอรีเซ็ตรหัส) ⇄ ปุ่ม **«หน้าเซลล์»** เมื่ออยู่ในหน้าตั้งค่า
- **Admin ที่ไม่มีรหัสเซลล์** ใช้ได้เฉพาะหน้าตั้งค่า เข้าหน้าเซลล์ไม่ได้

### บัญชีร้านค้า (`/admin/stores/accounts`)

หน้านี้แบ่งเป็นกล่อง **คำขอรีเซ็ตรหัส (N)** · **รออนุมัติ (N)** · **ร้านค้าที่อนุมัติแล้ว (N)** (Creator เห็น **ถูกปฏิเสธ (N)** เพิ่ม)

**การเปิดบัญชีให้ร้านค้าใหม่** ทำได้ 2 ทาง
1. **ร้านขอเอง** — ร้านกรอกอีเมลที่หน้าเข้าสู่ระบบและเลือก VDA ของตน คำขอจะขึ้นในกล่อง "รออนุมัติ"
   → ตรวจ/เลือก VDA ให้ถูก แล้วกด **«อนุมัติ»** (ต้องมี VDA ก่อนจึงจะอนุมัติได้)
2. **แอดมินเพิ่มให้** — ในกล่อง "ร้านค้าที่อนุมัติแล้ว" กด **«เพิ่มบัญชีร้านค้า»** กรอกอีเมล เลือก VDA แล้วกด «เพิ่มบัญชี»
   (บัญชีจะถูกอนุมัติทันที แอดมินไม่ต้องตั้งรหัสผ่านให้)

**ทุกครั้งที่อนุมัติ · เพิ่มบัญชี · หรือรีเซ็ตรหัส ระบบจะแสดงรหัสตั้งค่า (`XXXX-XXXX`)** ในกล่องสีเขียว
กด «คัดลอก» แล้วส่งให้ร้าน (ทางไลน์ / โทร ฯลฯ — ระบบไม่ได้ส่งให้เอง)
- ใช้ได้ครั้งเดียว ภายใน 72 ชม.
- **รหัสแสดงเพียงครั้งเดียว** ปิดกล่องแล้วดูซ้ำไม่ได้ ถ้าหายหรือหมดอายุ กด **«ออกรหัสตั้งค่าใหม่»** ที่แถวของร้าน
- แถวของร้านที่ยังไม่ได้ตั้งรหัสจะบอกว่า "รอร้านตั้งรหัส (รหัสตั้งค่าใช้ได้ถึง …)" หรือ "ไม่มีรหัสตั้งค่าที่ใช้ได้"

**รีเซ็ตรหัสผ่าน** เมื่อร้านกด «ลืมรหัสผ่าน?» หรือ «แจ้งแอดมินให้รีเซ็ตรหัส» คำขอจะขึ้นในกล่อง "คำขอรีเซ็ตรหัส"
กด **«รีเซ็ตรหัส»** แล้วส่งรหัสตั้งค่าที่ได้ให้ร้าน ร้านจะใช้รหัสนั้นตั้งรหัสผ่านใหม่

### โปร C4 เดือนนี้ (`/admin/promotions/c4`)

ตรวจสอบโปร C4 ของเดือนปัจจุบัน **เลือกดูรายคลังได้** และ **«ส่งออก Excel» กลุ่มโปรตามคลัง / แบรนด์ / กลุ่มสินค้าที่เลือก**
มีการ์ดสรุปจำนวนกลุ่มโปร · SKU ที่มีแถวโปร · แถวไม่มีสิทธิประโยชน์ · SKU ที่ไม่มีใน master
และบอกจำนวนกลุ่มที่ "ร้านยังไม่เห็น" เพราะช่วงวันที่ยังไม่เริ่มหรือหมดไปแล้ว

### สิทธิ์เซลล์-VDA (`/admin/system/vda-sales`)

ตาราง "รหัสเซลล์ · อีเมล · VDA" หนึ่งแถวต่อรหัสเซลล์ บอกว่ารหัสนั้นดูแลคลังไหน และอีเมลไหนเข้าใช้งานในฐานะรหัสนั้นได้

- **อีเมลที่ผูกไว้ = ทางเดียวที่เซลล์เข้าระบบได้** (ตั้งแต่ 28 ก.ย. 2569 ไม่ใช้ไฟล์ cross_salesman แล้ว) —
  อีเมลที่ยังไม่ได้ผูกกับรหัสใด login ฝั่งเซลล์ไม่ได้
- **เพิ่มอีเมลให้รหัสที่มีในตาราง** กด «+ อีเมล» ในแถว พิมพ์อีเมล (หลายอันคั่นด้วยจุลภาค) แล้วกด Enter หรือ «เพิ่ม»
- **รหัสที่ยังไม่อยู่ในตาราง** กรอกรหัสกับอีเมลในช่องด้านบนแล้วกด «กำหนดอีเมล»
- **Admin เอาอีเมลออกไม่ได้ และผูกรหัสให้อีเมลของผู้ดูแลระบบไม่ได้** — ต้องติดต่อ Creator
- **หนึ่งอีเมลผูกได้ 1 รหัสเซลล์เท่านั้น** (ตั้งแต่ 30 ก.ย. 2569) — ผูกรหัสที่สองจะขึ้นว่า "ผูกกับรหัสอื่นอยู่แล้ว"
  ต้องให้ Creator เอาอีเมลออกจากรหัสเดิมก่อน · หนึ่งรหัสยังมีได้หลายอีเมลเหมือนเดิม
- ตัวกรอง: **มี VDA** · **ยังไม่มีอีเมล** (รหัสที่ดูแลคลังแต่ยังไม่มีใครเข้าใช้งานได้) · **ทั้งหมด** · สลับดู **ตามรหัส / ตาม VDA**
- **มีผลทันที** ทั้งการเพิ่มและการเอาออก — ผู้ใช้ที่เข้าระบบค้างอยู่จะได้สิทธิ์ใหม่ในการกดครั้งถัดไป
  ถ้าเอาออกแล้วอีเมลนั้นไม่เหลือรหัสเซลล์เลย ผู้ใช้จะถูกพาไปหน้าเข้าสู่ระบบ

เมื่อเข้า `/admin` ระบบจะนำไปยังหมวดแรก («ข้อมูล › Sync & สถานะ») โดยอัตโนมัติ

| หมวด | แท็บ | หน้าที่ |

| | «ดูข้อมูลดิบ» `/admin/data/raw` | เปิดดูไฟล์และตารางที่ sync มาในรูปแบบดิบ · **ลากขอบหัวคอลัมน์เพื่อขยาย** ดับเบิลคลิก = กว้างพอดีไม่ตกบรรทัด (จำไว้ในเครื่องต่อตาราง) |

> ยังคงใช้งานได้ ระบบจะนำไปยังหน้าใหม่โดยอัตโนมัติ

### Creator ในหน้าเซลล์

- เข้า `/sales/orders` ได้เสมอ (หรือกด «ดูออเดอร์ทั้งหมด (ไม่จำกัด scope)» ที่หน้ามุมมองเซลล์) และ **เห็นออเดอร์ทุกร้าน**
  ตัวเลือก VDA มี "ทุก VDA" · กลับศูนย์ Admin ได้ทางลิงก์ **"กลับศูนย์ Admin"**
- **«กรองตามรหัสเซลล์»** (ใต้ตัวเลือก VDA) พิมพ์ค้นด้วยรหัส · VDA · อีเมลได้ แล้วเลือกรหัส จะเห็นออเดอร์ของทุก VDA
  ที่รหัสนั้นดูแล · ตัวเลือก VDA ด้านบนจะเหลือเฉพาะคลังของรหัสที่เลือก · เลือก «ทุกรหัส» หรือกด × เพื่อล้าง
- การ์ดออเดอร์และหัวรายละเอียดแต่ละใบบอก **"เซลล์ S091, …"** = รหัสเซลล์ที่ดูแลคลังนั้น

### การเปิดบัญชีร้าน · เพิ่มคลัง VDA ใหม่

การเปิดบัญชีร้านทำเหมือน [Admin](#บัญชีร้านค้า-adminstoresaccounts) · ถ้าต้องให้ร้านตั้ง MIN/MAX เองได้
ติ๊ก «จัดการ min/max» ตอนเพิ่มบัญชี หรือกดปุ่ม «จัดการ min/max» ที่แถวของร้าน

การเพิ่มคลัง VDA ใหม่ดำเนินการที่ `/admin/data/warehouses` โดยเพิ่มรหัสคลังและรหัสลูกค้าผ่านหน้าจอได้โดยตรง
**ไม่ต้องแก้ไขไฟล์ตั้งค่าบนเซิร์ฟเวอร์** ค่าที่กำหนดไว้ใน `.env` ใช้เป็นค่าตั้งต้นครั้งแรกเท่านั้น
หากข้อมูลไม่ตรงกัน ระบบจะยึดข้อมูลที่บันทึกไว้ในฐานข้อมูล

### บันทึกการทำงาน (`/admin/system/audit`)

ดูย้อนหลังได้ว่า **ใคร** (อีเมล + ป้าย Creator / Admin / เซลล์) **ทำอะไร** กับ **ร้าน / อีเมล / รหัสไหน** เมื่อไหร่ (เวลาไทย)

- จดทุกการกระทำในหน้าตั้งค่าที่แก้ข้อมูล: อนุมัติ / ปฏิเสธ / เพิ่ม / ลบบัญชีร้าน · รีเซ็ตรหัสผ่าน · เปลี่ยน VDA อีเมล
  หรือสิทธิ์ MIN/MAX ของร้าน · เพิ่ม / ลบผู้ดูแล · ผูก / ยกเลิกรหัสเซลล์ · แก้ทะเบียนคลัง · แก้ MIN/MAX · หยุดสั่ง /
  ยกเลิกหยุดสั่ง · สั่งดึงข้อมูล Fabric
- และ **การลบออเดอร์** ทุกครั้ง ไม่ว่าใครเป็นคนลบ (บอกร้าน วันที่สั่ง และเลข PO ที่ถูกลบไปด้วย)
  รวมถึง **การบันทึกผลตรวจ PO ที่ ERP ไม่ตอบ** ("แก้สถานะ ERP ไม่ตอบ")
- ค้นหาด้วยอีเมลหรือรหัส และกรองตามประเภทการทำงานได้ · ครั้งละ 100 แถว กด «โหลดเพิ่ม» เพื่อดูเก่ากว่านั้น
- **ไม่เก็บรหัสตั้งค่าหรือรหัสผ่าน** · เริ่มบันทึกตั้งแต่ 29 ก.ย. 2569

### มุมมองทดสอบ (เข้าดูโดยไม่ต้องทราบรหัสผ่าน)

**สงวนไว้สำหรับ Creator เท่านั้น** ผู้ใช้อื่นไม่สามารถเรียกใช้ได้ ระหว่างอยู่ในโหมดนี้จะมีแถบสีเหลือง "โหมดทดสอบ Admin"
ด้านบน ออกจากโหมดนี้ได้ด้วยปุ่ม **«กลับศูนย์ Admin»** บนแถบนั้น

- **มุมมอง VDA** (`/admin/preview/vda`) เลือกรหัส VDA ที่ต้องการ แล้วดูสต็อกและสั่งสินค้าเหมือนผู้ใช้งานจริง
  (ปุ่มออกจากระบบจะเปลี่ยนเป็น «ออกจาก VDA»)
- **มุมมองเซลล์** (`/admin/preview/sales`) ค้นหาแล้วเลือกเซลล์/รหัส เพื่อดูออเดอร์ที่เขาเห็น (scope เดียวกับ login จริง)
  — **ดูได้อย่างเดียว** แก้ไข / อนุมัติ / ลบ / รับทราบไม่ได้ ถ้ากดจะขึ้นข้อความ
  "มุมมองทดสอบดูได้อย่างเดียว — ออกจากมุมมองเซลล์ก่อน แล้วค่อยแก้ไขในบัญชีของคุณเอง"

### สัญลักษณ์แจ้งเตือนบนเมนู

จุดสีแดงหรือตัวเลขบนเมนูหมายถึงมีรายการที่ต้องตรวจสอบ

| ตำแหน่ง | ความหมาย | การดำเนินการ |
|---|---|---|
| ข้อมูล → Sync & สถานะ | รอบดึงข้อมูลล่าสุดล้มเหลว | ตรวจสอบสาเหตุแล้วสั่งดึงใหม่ หากล้มเหลวซ้ำโปรดแจ้งทีมที่ดูแล Fabric |
| ร้านค้า → บัญชีร้านค้า | มีคำขอเปิดบัญชีหรือขอรีเซ็ตรหัสรอดำเนินการ (Admin ก็เห็น) | เข้าไปดำเนินการอนุมัติ / รีเซ็ต |
| โปรโมชั่น → โปร C4 เดือนนี้ | ข้อมูลโปรโมชันของเดือนปัจจุบันยังไม่พร้อม | ตรวจสอบว่าไฟล์โปรโมชัน sync มาครบถ้วนหรือไม่ |

## ปัญหาที่พบบ่อย

### ร้านค้าเข้าสู่ระบบไม่ได้ ขึ้นว่า "บัญชีของคุณรอการอนุมัติจากแอดมิน"

คำขอถูกส่งเรียบร้อยแล้ว อยู่ระหว่างรอแอดมินอนุมัติที่ `/admin/stores/accounts`
โปรดติดต่อแอดมินเพื่อเร่งดำเนินการ และขอรับ **รหัสตั้งค่า** หลังอนุมัติ

### ตั้งรหัสผ่านครั้งแรกไม่ได้ เพราะไม่มีรหัสตั้งค่า หรือรหัสใช้ไม่ได้

รหัสตั้งค่าใช้ได้ครั้งเดียวและหมดอายุใน 72 ชม. และแอดมินเห็นรหัสได้ครั้งเดียวตอนออก
ให้แอดมินกด **«ออกรหัสตั้งค่าใหม่»** (หรือ «รีเซ็ตรหัส») ที่แถวของร้านใน `/admin/stores/accounts` แล้วส่งรหัสใหม่ให้

### กรอกรหัสผ่านผิดหลายครั้ง ระบบแสดงข้อความ "พยายามบ่อยเกินไป"

ระบบมีกลไกป้องกันการคาดเดารหัสผ่าน กรุณารอตามระยะเวลาที่ระบบแจ้งแล้วลองใหม่
หากไม่สามารถระบุรหัสผ่านได้ โปรดกด «ลืมรหัสผ่าน?» แล้วแจ้งแอดมิน

### ระบบนำกลับไปยังหน้าเข้าสู่ระบบเอง

session หมดอายุตามกำหนด 7 วัน สามารถเข้าสู่ระบบใหม่ได้ทันที ข้อมูลที่ส่งไปแล้วไม่สูญหาย
(เซลล์ที่ถูกเอาอีเมลออกจากทุกรหัสเซลล์ก็จะถูกพากลับหน้าเข้าสู่ระบบเช่นกัน)

### ข้อมูลบนหน้าจอไม่เป็นปัจจุบัน

1. กดปุ่ม **ตรวจข้อมูลใหม่** (ไอคอนลูกศรวน) ที่แถบสรุปของหน้าสต็อก
2. ตรวจสอบข้อความ "ข้อมูล ณ" หากเปลี่ยนเป็น "ข้อมูลค้าง" สีเหลืองหรือสีแดง หมายถึงระบบดึงข้อมูลไม่สำเร็จ
   โปรดแจ้งแอดมิน
3. Creator สามารถสั่งดึงข้อมูลใหม่ได้ที่ `/admin/data/sync`

### หน้าจอแสดงข้อความ "เกิดข้อผิดพลาด" พร้อมรหัสอ้างอิง

**กรุณาบันทึกภาพหน้าจอให้เห็นรหัสอ้างอิงดังกล่าว** แล้วส่งให้ทีมพัฒนา เนื่องจากรหัสนี้
ใช้ตรวจสอบสาเหตุใน log ได้โดยตรง ทั้งนี้สามารถเลือก "ลองใหม่" ก่อนได้
เนื่องจากบางกรณีเป็นปัญหาชั่วคราว

### เลือก "ยืนยันส่ง" ไม่ได้

ปุ่มจะไม่สามารถใช้งานได้**เฉพาะกรณี**ที่ยังไม่มีรายการที่จำนวนมากกว่า 0 (ทุกรายการเป็น 0)

ธงแดงไม่ได้ห้ามส่งออเดอร์ ระบบจะแสดงกล่องข้อความให้ยืนยันแทน
หากพบว่าปุ่มไม่สามารถใช้งานได้ทั้งที่ระบุจำนวนแล้ว **กรณีนี้ถือเป็นข้อผิดพลาดของระบบ**
โปรดแจ้งทีมพัฒนาพร้อมภาพหน้าจอ

### อนุมัติออเดอร์ไม่ได้ ปุ่มเป็นสีจาง

ดูข้อความเหนือปุ่ม
- "มี N รายการที่รอร้านยืนยัน" → รอร้านค้ากดยืนยันหรือปฏิเสธที่หน้า `/history` ของร้าน หรือติดต่อร้านโดยตรง
  หากไม่ต้องการรอ ให้ลดจำนวนกลับเท่าที่ร้านสั่ง (ปลดสถานะรอยืนยันทันที) หรือเอาติ๊กรายการนั้นออกแล้วอนุมัติเฉพาะที่เลือก
- แผงแบ่ง PO ขึ้นข้อความสีแดง → สินค้ากลุ่มโปรเดียวกันถูกแยกคนละใบ ให้ย้ายกลับมาอยู่ใบเดียวกัน
- อยู่ในมุมมองทดสอบเซลล์ → โหมดนี้ดูได้อย่างเดียว

### เปลี่ยนสถานะ PO ไม่ได้ ตัวเลือกเป็นสีเทา

ใบนั้นกำลังส่งเข้า ERP หรือเข้า ERP แล้ว (หรือ «ERP ไม่ตอบ — รอตรวจ») ซึ่งเปลี่ยนได้แค่เป็น «รับของแล้ว»
ถ้าเป็น «ERP ไม่ตอบ — รอตรวจ» ให้ตรวจกับทีม ERP แล้วบันทึกผลในรายละเอียด PO ก่อน (ดู [ส่ง PO เข้า ERP](#ส่ง-po-เข้า-erp))

### เซลล์เข้าสู่ระบบได้แต่ไม่พบออเดอร์

โปรดตรวจสอบตามลำดับ

1. อีเมลของท่านผูกกับรหัสเซลล์ที่ถูกต้องหรือไม่ — ดูได้ที่แท็บ «สิทธิ์เซลล์-VDA» (ให้ Admin / Creator ตรวจ)
2. รหัสเซลล์ของท่านดูแลคลัง VDA ใดบ้าง (มาจากทะเบียน VDA ขององค์กร)
3. หากท่านถือหลายรหัส ให้เลือกปุ่ม **«ดูออเดอร์ทุก VDA ของฉัน»** หรือสลับรหัสที่ช่อง «รหัสเซลล์»
4. ตรวจตัวกรองสถานะ — ค่าเริ่มต้นคือ «รออนุมัติ» ออเดอร์ที่ตัดสินแล้วต้องเลือก «อนุมัติแล้ว» / «ทั้งหมด»

ระบบจะแสดงแถบข้อความ "รหัสนี้ไม่มี VDA ที่ดูแล" หากเป็นกรณีที่ 2 โปรดแจ้งแอดมิน

### จำนวนของแถมในรายงานสูงผิดปกติ

อาจเกิดจากการนับของแถมของกลุ่มโปรโมชันซ้ำซ้อน โปรดแจ้งทีมพัฒนาพร้อมเลข PO (หรือชื่อร้านและวันที่สั่ง ถ้ายังไม่ได้ออก PO)
(ของแถมของกลุ่มโปรโมชันเป็นสิทธิ์ของทั้งกลุ่ม ไม่ใช่ของแต่ละรายการ ซึ่งระบบมีกลไกป้องกัน
การนับซ้ำอยู่แล้ว)

### เปิดดูเอกสาร PO ไม่ได้

ระบบจะประกอบเอกสารขึ้นใหม่จากฐานข้อมูลโดยอัตโนมัติเมื่อไฟล์ต้นฉบับไม่พบ
หากยังไม่สามารถเปิดได้ โปรดแจ้งทีมพัฒนาพร้อมเลขที่ PO

## คำศัพท์ที่ควรทราบ

| คำศัพท์ | ความหมาย |
|---|---|
| **VDA** | คลังสินค้าที่บริหารจัดการสต็อกด้วยตนเอง (Vendor Distribution Agent) |
| **ออเดอร์** | รายการสินค้าที่ร้านส่งให้เซลล์ตรวจและอนุมัติ |
| **PO / ใบสั่งซื้อ** | เอกสารที่ออกหลังจากเซลล์อนุมัติออเดอร์ ส่งต่อฝ่ายจัดซื้อและระบบ ERP (ออเดอร์หนึ่งใบแบ่งเป็นหลาย PO ได้) |
| **ERP** | ระบบกลางขององค์กรที่รับ PO เข้าไปดำเนินการต่อ — «เข้า ERP แล้ว» ยังไม่ได้แปลว่าออกบิลแล้ว |
| **CVD** | Cover Days — จำนวนวันที่สินค้าคงเหลือเพียงพอต่อการขาย |
| **MIN / MAX** | เป้าหมายจำนวนวันที่ควรมีสินค้าคงคลัง (ค่าต่ำสุดและค่าสูงสุด) |
| **หีบ** | หน่วยสั่งซื้อมาตรฐานของระบบ หน่วยชิ้นใช้แสดงเฉพาะเศษที่ไม่ครบหีบ |
| **C4** | ตารางราคาและโปรโมชันกลางขององค์กร |
| **โปรโมชันแบบกลุ่ม (pooled)** | โปรโมชันที่รวมยอดสินค้าหลาย SKU เข้าด้วยกัน ของแถมเป็นสิทธิ์ของทั้งกลุ่ม ไม่ใช่ของแต่ละรายการ |
| **ธงราคา** | สัญลักษณ์แสดงว่าราคาบนบรรทัดนั้นแตกต่างจากราคากลาง C4 (ป้าย "ราคาต่างระบบ") |
| **หยุดสั่ง** | สินค้าที่ร้านแจ้งไม่ให้ระบบแนะนำสั่ง (มีช่วงวันหรือถาวร) เซลล์ได้รับแจ้งอัตโนมัติ |
| **รหัสตั้งค่า** | รหัส 8 ตัว (`XXXX-XXXX`) ที่แอดมินออกให้ร้านเพื่อตั้งรหัสผ่านครั้งแรกหรือหลังรีเซ็ต ใช้ได้ครั้งเดียวภายใน 72 ชม. |
| **รหัสเซลล์** | รหัสพนักงานขาย (เช่น S091) แต่ละรหัสดูแลคลัง VDA ตามทะเบียนองค์กร และเข้าระบบได้ด้วยอีเมลที่ผูกไว้ |
| **Creator / Admin** | Creator = ผู้ดูแลสูงสุด ทำได้ทุกอย่าง · Admin = ผู้ดูแลที่ Creator เพิ่ม ใช้หน้าตั้งค่าได้บางส่วน |
| **sync** | การดึงข้อมูลสินค้า ราคา และยอดขายจากระบบกลาง ดำเนินการอัตโนมัติทุกคืนเวลา 03:30 น. |
